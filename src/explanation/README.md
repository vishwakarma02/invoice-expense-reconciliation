# Explanation Agent

The Explanation Agent turns matching and anomaly findings into plain-language
guidance for finance clerks. It creates one explanation for each invoice or
bank-payment matching exception and each Anomaly Agent finding, carries the
verified amounts and duplicate reference where available, and retrieves
relevant Markdown policy passages from `data/policies` with deterministic
keyword ranking.

LLM generation is optional and disabled by default. Set
`EXPLANATION_LLM_ENABLED=true` and configure
`AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_KEY`, and
`AZURE_OPENAI_DEPLOYMENT` in the project `.env` to enable it. The model
receives the issue summary, structured expected/found amounts, and retrieved
policy passages. The amount fields and evidence citations in the report are
retained from deterministic matching and policy retrieval, not generated by
the model. If generation fails, the failure is logged and a deterministic
explanation is returned.

When a matching check computes both values, the issue and explanation include
the expected amount, found amount, and currency. Examples include invoice unit
price versus PO unit price, calculated line totals, tax totals, invoice totals,
and bank debit versus invoice total. Amounts are not inferred for issues that
do not have a supported numeric comparison.

Run the full pipeline with `python run_pipeline.py`, or run the explanation
stage independently from the repository root:

```powershell
python run_explanation.py
```

By default, the agent reads `data/output/matching_output.json` and writes
`data/output/explanation_output.json`. To include anomaly findings, pass the
Anomaly Agent report with `--anomaly-input`. The module CLI also accepts
`--input` and `--output` overrides:

```powershell
python -m src.explanation.batch_cli `
  --input data/output/matching_output.json `
  --output data/output/explanation_output.json `
  --anomaly-input data/output/anomaly_output.json
```

Run matching first (`python run_matching.py`) if the matching JSON was created
before expected/found amount fields were added; the full pipeline regenerates
both matching and explanation outputs in sequence.

Each report item includes the source document, invoice number when available,
issue or anomaly type, anomaly severity when applicable, explanation,
recommended next step, expected/found amounts when calculated, currency, and
source evidence.

Run its focused tests with:

```powershell
python -m pytest tests/test_explanation_agent.py -q
```

The FastAPI demo presents explanations, citations, HITL review cases, and
draft-only correspondence in one UI. See the repository README for startup and
configuration instructions.
